# Contributing

Thanks for improving this template.

## Principles

- Keep content organization-neutral and broadly reusable.
- Avoid hardcoding internal-only URLs, identifiers, or credentials.
- Prefer clear placeholders like `<replace-with-...>` when something must be customized.
- Keep the repository structure simple and well linked.

## Content Rules

- Use `[[...]]` links between repository notes.
- Keep note titles concise and searchable.
- Follow the naming conventions in [[Structure]].
- Update related guidance when structure or conventions change.

## Typical Contribution Flow

1. Create a feature branch.
2. Make focused, documented changes.
3. Verify that links and paths still make sense.
4. Open a pull request or merge request with a clear summary.

## Validation Checklist

- No private organization names remain.
- No secrets or tokens are committed.
- Naming conventions are still coherent.
- The template remains understandable for non-software teams too.
